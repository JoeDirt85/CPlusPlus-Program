# CPlusPlus-Program
Repository for class projects

#Summarize the project and what problem it was solving.

  For this project, I was tasked with creating a program that would open and read a .txt file, and would be able to count the frequency that an item was listed. 
To do this, the program would open and read the file, then go through each line of the file and add to the count. It would then store and backup the data before closing      the file. With the count data, the program would then allow for user input to search for the frequnecy of a specific item, all items or display a histogram of the items.

#What did you do particularly well?

  What I think I did well for this program, was creating an easy to read program. I believe I did this well, because I used the principles of OOP, to divide the program into three seperate class files, while having as little coding done in the main file as possible. I had one class file, that contained a majority of the functions that were instrumental in running the program. The other class file was used to create the display that was used for the user to interact with. Doing this, seperates the different parts of the program, into sections that allow for outside viewers to more easily be able to read and adjust the program if neccissary.

#Where could you enhance your code? How would these improvements make your code more efficient, secure, and so on?

  I think I could have improved the menu display function. My version, I manually made the display and counted out the amount of asterics needed to encapsulate the body of text of the menu. So to improve it, I think I could have made a function that would print the proper amount of asterics and space the text accordingly, rather then me having to manually type out each asteric and get the correct spacing for each column of the menu. 

#Which pieces of the code did you find most challenging to write, and how did you overcome this? What tools or resources are you adding to your support network?

  I think the hardest part of the code had to have been the loop for the histogram. Not because it was overtly complicated, but rather that I was overthinking it and making it more complicated. I spent a bit of time thinking of how the layout of the histogram would look, and thought it should look more like an actual chart, rather than some asterics in the command line. So, once I stopped overthinking it, I was able to make the loop without much trouble.

#What skills from this project will be particularly transferable to other projects or course work?

  I believe the ability to open and read files will be an extremely trasnferable skill. That is because I imagine that when you take projects beyond the command line, that the input of the user could potentially be something that is considered to be in a different file than the program they are interacting with. 

#How did you make this program maintainable, readable, and adaptable?

  I did this by following proper OOP techniques and by making sure to leave in line comments, describing what each section of the program was inteded for. So that if someone else had to go over the code to either fix or add onto, they would be able to see refrence points left by me and could look into the different files to find those functions.
